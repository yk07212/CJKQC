# Feature: Plain xyz Parser <!-- rq-bfac850d -->

Plain xyz files carry a structure and nothing else: an atom-count line, a
comment line, and one row per atom (`N`, `x y z`, in Ångström), with frames
concatenated back to back for multi-frame files. The plain-xyz parser turns
such a file into exactly one record describing its **last complete frame**
(the framework's final-frame rule, `rqm/parser-framework.md`), carrying the
geometry in Ångström and, when the frame's comment line names an electronic
energy, that energy in hartree.

The plain-xyz format carries no program banner: it is recognized
structurally, by the shape of the opening lines, and the standard registry
registers this parser last so any banner-bearing file is claimed first
(`rqm/parsers/conformance.md`). Charge, multiplicity, frequencies, and all
other observables are absent — an xyz file simply does not carry them.

The comment line is otherwise opaque. One label is honored because JKQC
itself writes energies into xyz comments: a token `Electronic_Energy:`
(case-insensitive) followed by a number records that value as
`electronic_energy` (hartree). Every other comment token — including
`Free_Energy:`, which is a derived quantity — is ignored.

## Feature API <!-- rq-9d65a814 -->

### Types <!-- rq-f30931da -->

- `XyzParser` — unit struct implementing the framework `Parser` trait with <!-- rq-aa33eaea -->
  `program()` = `Program::XYZ`. Lives in `src/parser/xyz.rs`, re-exported
  by the library root. Detection and extraction use the shared
  `read_geometry_table` and `parse_fortran_f64` helpers
  (`rqm/parser-framework.md`).

### Detection <!-- rq-fd7af40a -->

- `detect(head)` returns `Some(0)` — the structural signature begins at the <!-- rq-07f351b5 -->
  first byte — when: the first line is a positive integer in ASCII digits, the
  second line exists (any content, including empty), and the third line is a
  well-formed atom row (element symbol followed by three fields that parse via
  `parse_fortran_f64`); otherwise `None`.
- The structural test never consults the file name or extension.

### Extraction <!-- rq-5d0be798 -->

- A **frame** is: count line `N`, comment line, then exactly `N` atom rows;
  a row is `read_geometry_table`-conformant with `Symbol(0)` symbol column,
  coordinate columns 1–3, and `LengthUnits::Angstrom`. Symbols normalize to
  title case; coordinates are stored unchanged.
- Frames are read from the visible content in order; the record's geometry
  is the last frame that is complete (its count line, comment, and all `N`
  rows visible). `electronic_energy` is read from that frame's comment line
  only when the `Electronic_Energy:` label is present and its following
  token parses; a malformed value yields an absent energy, not a failure.
- On uncovered windows the parser scans only visible lines; a frame whose
  count line lies in the elided middle is not reconstructed, and geometry
  comes from the last fully visible frame (absent if none is complete).

### Status Classification <!-- rq-1810d098 -->

- `ok` — the last frame is complete and valid. <!-- rq-7d8c7128 -->
- `truncated` — the content ends inside a frame: a count line with fewer <!-- rq-f8c76b21 -->
  than `N` following rows before the end of the visible content, or a
  missing comment/row. The geometry holds the previous complete frame if
  any; the error names the incomplete frame.
- `failed` — the first frame's rows are not parseable geometry (unknown <!-- rq-9be2fad5 -->
  element symbol, unreadable coordinates); error names the malformed frame.
- No parser panic on any content; `N` of zero or a non-integer count line
  is a non-claim (handled by detection), not a status.

## Out of Scope <!-- rq-4c73955a -->

- Supercell/extended-xyz variants (lattice vectors, `properties=` column
  prefixes); rows outside the plain `symbol x y z` shape end a table.
- Energy labels other than `Electronic_Energy:`.
- Any observable an xyz file cannot carry (see above).
