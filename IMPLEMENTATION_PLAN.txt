CJKQC v1 — MILESTONE OVERVIEW
==============================
High-level roadmap only. The details of every milestone are worked out
per-feature with the rr-plan skill into rqm/<feature>.md before any code is
written; this file just fixes the order and the boundaries between milestones.

Ground rules for all milestones (from rqm/ARCHITECTURE.md):
- Store observables only; derive everything else at request time.
- No panics on bad input — failed/truncated jobs become status records.
- hartree internally; unit conversion only at print/export.
- Old .jsonl databases must always stay loadable.
- Gate for every milestone: CI green (fmt, clippy, tests, coverage).

Milestones
----------
0. Scaffolding
   Crate skeleton, clap CLI shell, minimal deps (clap, serde, serde_json).

1. Record schema + database
   JSON Lines record of primary observables; append, load, merge databases.

2. Format detection + parser framework
   Content-based sniffing (never by extension); parser trait + registry;
   shared extractors; failed/truncated -> status records.

3. Parsers (conformance-driven, one rr-plan doc each, in this order)
   plain xyz -> XTB -> ORCA -> Gaussian -> MRCC.
   Each is done when it passes the conformance suite over
   tests/fixtures/ (see tests/fixtures/MANIFEST.md for what exists
   and what is still missing).

4. Collection + composition resolution
   `cjkqc <files>` builds a database; JKQC filenames -> composition with
   CLI/record overrides; resolved values stored as explicit fields.

5. Filtering and manipulation
   Subset, sort, print, cutoffs, uniqueness (RMSD), reacted/exploded
   detection — all pure functions over records.

6. Thermochemistry on demand
   ZPE/H/S/G(T) and corrections (BSSE, low-frequency, anharmonicity),
   formation/binding energies from a monomer reference database,
   derived-property registry, unit conversion.

7. Export and reporting
   xyz, movie.xyz, spreadsheet, property printing.

8. Hardening + release
   Robustness pass on hostile inputs, resolve open architecture questions,
   docs, end-to-end verification.

Dependency chain: 0-1-2 infrastructure -> 3 -> 4 -> 5/6/7 (independent of
each other, may be parallelized) -> 8.
